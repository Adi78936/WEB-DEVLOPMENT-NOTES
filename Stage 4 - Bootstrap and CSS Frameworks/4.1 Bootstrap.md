# 4.1 Bootstrap

## Interview preparation

Bootstrap is a frontend toolkit that provides a responsive grid, CSS utilities, styled components, and optional JavaScript-driven interactions. It helps teams build consistent interfaces quickly, but still requires semantic HTML, accessibility checks, and product-specific design decisions.

## What is Bootstrap?

Bootstrap includes:

- CSS styles and layout primitives, including its responsive grid.
- Utility classes for spacing, display, colors, typography, and other common styles.
- Component patterns such as buttons, cards, navbars, alerts, modals, and tables.
- JavaScript plugins for interactive components such as dropdowns, modals, accordions, and carousels.

Bootstrap styles do not replace understanding CSS. Components should be customized and tested to match the application rather than used as a substitute for design decisions.

## Installation using a CDN

A CDN can serve Bootstrap CSS and JavaScript without adding a package build step. Use URLs and version-specific integrity values from Bootstrap's official documentation:

```html
<head>
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <link
    href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/css/bootstrap.min.css"
    rel="stylesheet"
    integrity="sha384-..."
    crossorigin="anonymous">
</head>
<body>
  <!-- Page content -->
  <script
    src="https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/js/bootstrap.bundle.min.js"
    integrity="sha384-..."
    crossorigin="anonymous"></script>
</body>
```

The `...` is explanatory placeholder text, not a valid integrity hash. Copy the complete URL and matching `integrity` value from the official Bootstrap documentation when using a CDN. Never copy a hash from an unrelated release or file.

- The bundle includes Popper, which is used by components such as dropdowns and tooltips.
- CSS-only usage does not require the JavaScript bundle.
- The JavaScript bundle should generally be loaded after page markup or with an appropriate script-loading strategy.
- A CDN introduces a third-party network dependency. Consider availability, privacy, integrity, caching, and project policy.

### Package-manager installation

In a build-based project, install Bootstrap from the package manager and import its CSS into the application's entry point. Install only the dependencies required by the chosen version and project setup.

```js
import "bootstrap/dist/css/bootstrap.min.css";
```

Bootstrap JavaScript plugins may be imported individually when needed, or applications can use a framework-specific Bootstrap library. Avoid loading duplicate CSS or JavaScript bundles.

## Bootstrap file structure

A distributed build commonly includes:

- Compiled CSS (`bootstrap.css` or the minified `bootstrap.min.css`).
- Source maps and Sass sources in some distributions.
- JavaScript bundles (`bootstrap.js` and `bootstrap.bundle.js`, with minified versions).

The exact package contents depend on the Bootstrap release. The compiled CSS can be linked directly; Sass sources can support deeper customization when a build tool is configured.

## Containers and `container-fluid`

Containers provide horizontal padding and responsive layout widths:

```html
<div class="container">
  <div class="row"><div class="col">Content</div></div>
</div>
```

- `.container` uses responsive maximum widths at Bootstrap breakpoints.
- `.container-fluid` occupies the full available width at every breakpoint.
- `.container-{breakpoint}` becomes fluid until the specified breakpoint and then uses a responsive maximum width.
- Container width behavior is version-specific; check the documentation for the installed Bootstrap release.

Containers help center and align content. They do not automatically provide a page's entire layout.

## Grid system: rows and columns

Bootstrap's grid is based on containers, rows, and columns:

```html
<div class="container">
  <div class="row">
    <div class="col-12 col-md-8">Main content</div>
    <div class="col-12 col-md-4">Sidebar</div>
  </div>
</div>
```

- Rows organize columns and use gutters for spacing.
- The standard grid has 12 columns per row as a convenient layout scale.
- Column classes allocate widths at specified breakpoints.
- `.col` can create flexible equal-width columns.
- Rows should generally be placed within a container, and columns should be direct children of rows.
- Nested rows can be placed inside columns.

Bootstrap's grid is built with CSS and responsive breakpoint classes; a “12-column grid” does not mean that every layout must contain twelve visible elements.

## Breakpoints

Bootstrap responsive classes use minimum-width breakpoints. Common Bootstrap 5 breakpoint names are `sm`, `md`, `lg`, `xl`, and `xxl`; the exact width values are defined by the version and can be customized through Sass.

```html
<div class="col-12 col-md-6 col-xl-4">...</div>
```

This column occupies the full row by default, half the row at `md` and wider, and one third at `xl` and wider.

Do not assume breakpoints correspond exactly to named devices. They mark points where the layout changes.

## Responsive utilities

Responsive classes can alter display, alignment, spacing, and other styles at different breakpoints:

```html
<div class="d-none d-md-block">Visible at md and wider</div>
<div class="text-center text-lg-start">Responsive text alignment</div>
```

Utilities can make small layout adjustments convenient. Too many utility classes can make markup difficult to understand; extract a component or custom class when a repeated pattern needs a clear name.

## Typography utilities

Bootstrap offers utilities for headings, body text, alignment, wrapping, and other typographic settings:

```html
<p class="lead">Introductory text.</p>
<p class="text-body-secondary">Supporting detail.</p>
<h2 class="h4">A heading styled like a level-four heading</h2>
```

Use the appropriate HTML heading level for document structure even when a different visual size is needed. A CSS class should not replace meaningful heading semantics.

## Color utilities

Color utilities apply text, background, and other contextual colors:

```html
<p class="text-success">Saved successfully.</p>
<div class="bg-body-secondary">Supporting panel</div>
```

- Choose utilities that communicate meaning and fit the design system.
- Check color contrast, including dark mode.
- Never rely on color alone to convey success, error, or selection.
- Bootstrap color tokens and utility names can vary by version and theme.

## Spacing utilities

Spacing classes use margin and padding shorthands and responsive breakpoints:

```html
<div class="p-3 mb-4 px-md-5">Content with responsive spacing</div>
```

Common patterns include:

- `m-*`: margin; `p-*`: padding.
- Directional forms such as `mt-*`, `px-*`, or `my-*`.
- Responsive forms such as `mt-md-4`.
- `gap-*` for supported grid/flex layouts.

Bootstrap's spacing scale is based on Sass configuration and the selected version. Repeated custom spacing requirements may be better represented by design tokens.

## Buttons

```html
<button type="button" class="btn btn-primary">Prepare image</button>
<a class="btn btn-outline-secondary" href="/pipeline">View pipeline</a>
```

- Use `<button>` for an action and `<a>` for navigation.
- Pick a variant that reflects hierarchy and intent.
- Set an explicit button `type` inside forms when it should not submit.
- Bootstrap's `.btn` class styles controls; it does not automatically implement application behavior.

## Cards

Cards group related content:

```html
<article class="card">
  <div class="card-body">
    <h2 class="card-title">Image preparation</h2>
    <p class="card-text">Inspect a local preprocessing preview.</p>
    <a class="btn btn-primary" href="/workspace">Open workspace</a>
  </div>
</article>
```

Use cards when the content forms a meaningful group. Avoid wrapping every element in a card without an information-architecture reason.

## Navbar

A Bootstrap navbar styles responsive navigation:

```html
<nav class="navbar navbar-expand-lg bg-body-tertiary">
  <div class="container">
    <a class="navbar-brand" href="/">Retina Lab</a>
    <button
      class="navbar-toggler"
      type="button"
      data-bs-toggle="collapse"
      data-bs-target="#mainNavigation"
      aria-controls="mainNavigation"
      aria-expanded="false"
      aria-label="Toggle navigation">
      <span class="navbar-toggler-icon"></span>
    </button>
    <div class="collapse navbar-collapse" id="mainNavigation">
      <ul class="navbar-nav ms-auto">
        <li class="nav-item"><a class="nav-link" href="/overview">Overview</a></li>
        <li class="nav-item"><a class="nav-link" href="/pipeline">Pipeline</a></li>
      </ul>
    </div>
  </div>
</nav>
```

Use a meaningful navigation label, appropriate links, and a working collapse control. Test the toggler with keyboard and assistive technology; verify `aria-expanded` reflects the state.

## Dropdowns

Dropdowns require Bootstrap's JavaScript plugin and Popper:

```html
<div class="dropdown">
  <button
    class="btn btn-secondary dropdown-toggle"
    type="button"
    data-bs-toggle="dropdown"
    aria-expanded="false">
    Actions
  </button>
  <ul class="dropdown-menu">
    <li><a class="dropdown-item" href="/export">Export details</a></li>
  </ul>
</div>
```

Dropdowns are for a set of related actions or links, not a replacement for every navigation menu. Verify focus, dismissal, and keyboard behavior for the chosen version and configuration.

## Forms

Bootstrap provides form-control, form-select, checkbox, and validation styling:

```html
<div class="mb-3">
  <label for="email" class="form-label">Email address</label>
  <input id="email" class="form-control" name="email" type="email" required>
</div>
```

Bootstrap styles controls; labels, descriptions, validation logic, submission behavior, and server-side validation are still the application's responsibility. Never use only placeholder text as a form label.

## Modals

Modals show content in a dialog-like overlay. They need Bootstrap JavaScript:

```html
<button
  class="btn btn-primary"
  type="button"
  data-bs-toggle="modal"
  data-bs-target="#helpModal">
  Open help
</button>

<div class="modal fade" id="helpModal" tabindex="-1" aria-labelledby="helpModalTitle" aria-hidden="true">
  <div class="modal-dialog">
    <div class="modal-content">
      <div class="modal-header">
        <h2 class="modal-title fs-5" id="helpModalTitle">Image help</h2>
        <button type="button" class="btn-close" data-bs-dismiss="modal" aria-label="Close"></button>
      </div>
      <div class="modal-body">Choose an image to start a local preview.</div>
    </div>
  </div>
</div>
```

The Bootstrap plugin manages important dialog behaviors such as showing and hiding the modal and handling focus. Test focus entry and return, keyboard dismissal, accessible naming, and screen-reader behavior; do not assume styling alone creates an accessible dialog.

## Alerts

```html
<div class="alert alert-warning" role="alert">
  Model inference is not connected.
</div>
```

Alerts display feedback. Use a suitable role or live-region behavior when the message needs to be announced, and avoid using assertive announcements for non-urgent updates.

## Tables

```html
<div class="table-responsive">
  <table class="table table-striped">
    <caption class="visually-hidden">Image preparation steps</caption>
    <thead>
      <tr><th scope="col">Step</th><th scope="col">Status</th></tr>
    </thead>
    <tbody>
      <tr><th scope="row">Green-channel preview</th><td>Available</td></tr>
    </tbody>
  </table>
</div>
```

Use tables for tabular data, not for layout. Preserve captions and header relationships. `.table-responsive` provides horizontal scrolling at smaller widths.

## Accordions

Bootstrap's collapse plugin can support accordion-style sections:

```html
<div class="accordion" id="pipelineAccordion">
  <div class="accordion-item">
    <h2 class="accordion-header">
      <button
        class="accordion-button collapsed"
        type="button"
        data-bs-toggle="collapse"
        data-bs-target="#stageOne"
        aria-expanded="false"
        aria-controls="stageOne">
        Image preprocessing
      </button>
    </h2>
    <div id="stageOne" class="accordion-collapse collapse" data-bs-parent="#pipelineAccordion">
      <div class="accordion-body">Preview the green channel and local contrast.</div>
    </div>
  </div>
</div>
```

Use accordions when users benefit from controlling how much content is visible. Do not hide essential information by default without a good reason.

## Carousel

A carousel rotates through slides or content and requires Bootstrap JavaScript:

```html
<div id="studyCarousel" class="carousel slide">
  <div class="carousel-inner">
    <div class="carousel-item active">
      <img src="study-one.jpg" class="d-block w-100" alt="Original image preview">
    </div>
    <div class="carousel-item">
      <img src="study-two.jpg" class="d-block w-100" alt="Contrast-enhanced image preview">
    </div>
  </div>
  <button class="carousel-control-prev" type="button" data-bs-target="#studyCarousel" data-bs-slide="prev">
    <span class="carousel-control-prev-icon" aria-hidden="true"></span>
    <span class="visually-hidden">Previous slide</span>
  </button>
  <button class="carousel-control-next" type="button" data-bs-target="#studyCarousel" data-bs-slide="next">
    <span class="carousel-control-next-icon" aria-hidden="true"></span>
    <span class="visually-hidden">Next slide</span>
  </button>
</div>
```

Carousels can hide content and create motion. Provide named controls, pause behavior for automatic rotation, clear slide status where appropriate, and respect reduced-motion preferences. Do not auto-rotate essential content without careful usability consideration.

## Bootstrap Icons

Bootstrap Icons is a separate icon library/package from Bootstrap's core CSS and JavaScript. It can be installed from its official package or loaded as a versioned icon font/SVG resource according to project needs.

```html
<svg class="bi" aria-hidden="true"><use href="#download"></use></svg>
<span class="visually-hidden">Download</span>
```

The snippet requires the corresponding symbol to be available in the document or a correctly configured sprite. For an icon-only control, give the button an accessible name; decorative icons should generally be hidden from assistive technology.

## Customizing Bootstrap

Customization choices include:

1. **Utility classes:** convenient for local, small adjustments.
2. **Custom CSS after Bootstrap:** override variables or component styles carefully.
3. **Sass variables and source:** build a customized Bootstrap stylesheet when project tooling supports Sass.
4. **Theme tokens:** configure colors, typography, and component values consistently.

Prefer documented variables and a small set of intentional overrides. Avoid editing a generated Bootstrap distribution directly; dependency updates can overwrite those changes. Check whether a customization affects focus states, contrast, or responsive behavior.

## Bootstrap CSS vs. JavaScript

- Bootstrap CSS provides layout and visual styling.
- Bootstrap JavaScript provides behaviors for interactive components such as dropdowns, modals, and collapse.
- A component may use CSS classes for appearance and `data-bs-*` attributes to configure its JavaScript behavior.
- Do not load multiple copies of the Bootstrap JS bundle or combine incompatible major versions.

## Common interview questions

1. **What is Bootstrap?**  
   A frontend toolkit providing responsive CSS, layout utilities, components, and optional JavaScript plugins.

2. **What is the difference between `.container` and `.container-fluid`?**  
   `.container` has responsive maximum widths; `.container-fluid` spans the available width at every breakpoint.

3. **How does the grid work?**  
   Containers hold rows; rows organize columns; responsive column classes define track widths at breakpoints.

4. **Does Bootstrap require JavaScript?**  
   CSS-only styling and the grid do not; interactive plugins such as modals and dropdowns do.

5. **How should Bootstrap be customized?**  
   Use documented variables, utilities, a controlled custom stylesheet, or Sass compilation; do not modify vendored generated files directly.

6. **Does a styled Bootstrap form guarantee validation and accessibility?**  
   No. The application still needs meaningful labels, real validation, useful errors, and accessible behavior.

## Good practices

- Consult documentation for the exact Bootstrap version in use.
- Use correct, matching integrity hashes for CDN assets.
- Load only required JavaScript behavior.
- Use semantic elements and preserve accessible labels and states.
- Customize intentionally rather than layering many overrides.
- Test the responsive layout and interactive plugins with keyboard and screen reader.
