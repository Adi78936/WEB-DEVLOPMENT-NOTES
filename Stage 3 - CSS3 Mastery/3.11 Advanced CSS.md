# 3.11 Advanced CSS

## CSS variables (custom properties)

Custom properties centralize reusable values and can be scoped and themed:

```css
:root { --surface: #fff; --space: 1rem; }
.card { padding: var(--space); background: var(--surface); }
```

Use `var(--name, fallback)` when a fallback is appropriate. Custom properties inherit, so component-level overrides and theme changes are possible.

## `calc()`, `min()`, `max()`, and `clamp()`

```css
.container { width: min(100% - 2rem, 72rem); }
.panel { padding: max(1rem, 3vw); }
h1 { font-size: clamp(2rem, 5vw, 4.5rem); }
.main { height: calc(100dvh - 4rem); }
```

- `calc()` performs calculations combining compatible CSS units.
- `min()` chooses the smallest of its arguments.
- `max()` chooses the largest.
- `clamp(min, preferred, max)` bounds a preferred value.

These functions express responsive constraints without writing many media queries. Check that the selected value remains usable at zoom and small widths.

## `aspect-ratio`

```css
.preview { aspect-ratio: 16 / 9; }
```

Establishes a preferred ratio between width and height when one dimension is automatic. It can reserve layout space for media or responsive cards.

## `object-fit` and `object-position`

These properties control replaced content such as `<img>` and `<video>` inside a set-size box:

```css
.thumbnail {
  width: 12rem;
  aspect-ratio: 4 / 3;
  object-fit: cover;
  object-position: center 35%;
}
```

- `cover` fills the box and may crop.
- `contain` shows all content and may leave empty space.
- `fill` may distort aspect ratio.
- `object-position` controls alignment of the rendered content.

## Filters

```css
.muted-preview { filter: grayscale(1) contrast(1.1); }
```

CSS filters include `blur()`, `brightness()`, `contrast()`, `grayscale()`, `opacity()`, `saturate()`, and `drop-shadow()`. Filters alter visual presentation, not source image data. If a value communicates information, ensure it remains perceivable without relying on the filter alone.

## Blend modes

`mix-blend-mode` blends an element with its backdrop; `background-blend-mode` blends background layers:

```css
.overlay { mix-blend-mode: multiply; }
```

Blend results depend on the colors behind the element. Test contrast and unintended interactions with neighboring content.

## Clip paths and masks

```css
.portrait { clip-path: circle(48% at center); }
```

- `clip-path` clips the visible region to a geometric shape or path.
- CSS masks use an image or gradient as an alpha/luminance mask where supported.
- Clipping/masking changes appearance, not semantic structure. Do not obscure content or make essential information available only through a clipped visual.

## CSS nesting

Native CSS nesting allows related selectors to be grouped:

```css
.card {
  padding: 1rem;

  & > h2 { margin-top: 0; }
  &:hover { border-color: seagreen; }
}
```

Check browser and tooling support for the project's target. Nesting does not excuse deeply coupled selectors or excessive specificity.

## Container queries

Container queries adapt a component to its container instead of the viewport:

```css
.card-list { container-type: inline-size; }

@container (min-width: 32rem) {
  .card { display: grid; grid-template-columns: 8rem 1fr; }
}
```

Declare a query container on an ancestor. Container queries are useful when the same component appears in differently sized regions.

## Logical properties

Logical properties describe inline/block directions and adapt to writing modes:

```css
.card {
  margin-block: 1rem;
  padding-inline: 1.25rem;
  border-inline-start: 3px solid seagreen;
}
```

They are more adaptable than fixed physical directions such as `margin-left`, especially for right-to-left languages and vertical writing modes.

## Dark mode

Respond to the user's system preference:

```css
@media (prefers-color-scheme: dark) {
  :root { color-scheme: dark; --surface: #202622; --text: #f3f5f2; }
}
```

An application-controlled theme can use a class or `data-theme` attribute. Provide sufficient contrast in both themes and synchronize the visual theme with any theme control's accessible state. `color-scheme` informs the browser about supported native control colors; it does not create a complete theme.

## Scroll behavior and snapping

```css
html { scroll-behavior: smooth; }
.gallery { overflow-x: auto; scroll-snap-type: x mandatory; }
.gallery-item { scroll-snap-align: start; }
```

- Smooth scrolling can be useful for anchor navigation; respect reduced-motion preferences.
- Scroll snapping can guide scrolling, but overly strict snapping can make content difficult to navigate. Test keyboard and touch behavior.

## Interview review

1. What does `clamp()` do? Bounds a preferred value between a minimum and maximum.
2. What is the difference between viewport and container queries? Viewport queries use viewport conditions; container queries use an ancestor container's size.
3. What does `object-fit: cover` do? Fills a replaced-element box while potentially cropping content.
4. Why use logical properties? They adapt to writing direction and writing mode.
5. Does `color-scheme: dark` theme an entire site? No; it informs native browser UI. Author styles still need to define the page theme.
6. How do CSS filters differ from image processing? Filters visually change rendering; they do not necessarily modify the original image file or pixel data.

## Good practices

- Use advanced features to solve actual layout or interaction problems.
- Provide sensible fallbacks when required by supported browsers.
- Test contrast, zoom, reduced motion, and writing direction.
- Keep nesting shallow and component styles understandable.
- Check that scroll snapping and smooth scrolling do not hinder users.
