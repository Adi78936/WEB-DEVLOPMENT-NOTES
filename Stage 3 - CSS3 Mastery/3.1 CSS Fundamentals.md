# 3.1 CSS Fundamentals

## Interview preparation

CSS (Cascading Style Sheets) describes how HTML content is presented: colors, typography, spacing, layout, and responsive behavior. HTML provides structure and meaning; CSS controls presentation.

## Ways to add CSS

### Inline CSS

The `style` attribute applies declarations directly to one element:

```html
<p style="color: darkgreen;">A short note.</p>
```

It is useful for quick experiments or generated styles, but it mixes content with presentation, is hard to reuse, and is difficult to maintain. Inline declarations also have high author-origin precedence compared with ordinary stylesheet rules.

### Internal CSS

The `<style>` element defines styles in the document head:

```html
<head>
  <style>
    .notice { color: darkgreen; }
  </style>
</head>
```

Suitable for small single-document examples; larger sites usually benefit from shared stylesheets.

### External CSS

An external stylesheet is linked from the HTML:

```html
<link rel="stylesheet" href="styles.css">
```

It separates content from presentation, supports reuse across pages, and can be cached by the browser.

## CSS syntax

A CSS rule has a selector and a declaration block:

```css
.notice {
  color: #285d4b;
  padding: 1rem;
}
```

- `.notice` is the selector.
- `color` and `padding` are properties.
- `#285d4b` and `1rem` are values.
- A property/value pair is a declaration.
- Declarations normally end in semicolons.

## Selectors

Selectors identify the elements a rule applies to.

```css
/* Element */
p { line-height: 1.6; }

/* Class */
.card { padding: 1rem; }

/* ID */
#main { max-width: 70rem; }

/* Universal */
* { box-sizing: border-box; }

/* Grouping */
h1, h2, h3 { font-family: sans-serif; }

/* Descendant: any matching descendant */
article p { color: #555; }

/* Child: direct children only */
nav > a { text-decoration: none; }

/* Attribute */
input[type="email"] { border-color: teal; }
```

### Specificity overview

Among otherwise competing selectors, IDs generally outweigh classes/attributes/pseudo-classes, which outweigh element selectors. Specificity is a separate topic; selector order and the full cascade also matter.

Prefer classes for reusable component styling. IDs are best kept unique and are often more useful for document anchors and scripting than for styling.

## Pseudo-classes

A pseudo-class selects an element in a particular state or position:

```css
a:hover { color: #a4432f; }
button:focus-visible { outline: 3px solid orange; }
input:disabled { opacity: .6; }
li:first-child { font-weight: 700; }
```

Common examples include `:hover`, `:focus`, `:focus-visible`, `:active`, `:checked`, `:disabled`, `:first-child`, and `:not(...)`.

Do not communicate important information through hover alone; hover is unavailable on many touch devices.

## Pseudo-elements

Pseudo-elements style a specific part of an element or generate decorative content:

```css
.required-label::after {
  content: " *";
  color: firebrick;
}

p::first-line { font-weight: 600; }
```

Common examples: `::before`, `::after`, `::first-letter`, `::first-line`, and `::selection`. Generated content is best used decoratively; essential text should exist in the document.

## CSS comments

```css
/* Explain a non-obvious design decision. */
.toolbar { gap: 1rem; }
```

Comments are ignored by the CSS parser. Avoid leaving outdated comments or secrets in source files delivered to clients.

## Interview review

1. What is the difference between HTML and CSS? HTML describes structure/meaning; CSS describes presentation.
2. What are the parts of a CSS rule? A selector and a declaration block containing property/value declarations.
3. How does a child selector differ from a descendant selector? `>` selects direct children; whitespace selects any matching descendant.
4. How do a pseudo-class and pseudo-element differ? A pseudo-class selects a state/condition; a pseudo-element targets a part or generated content.
5. When should you prefer external CSS? For reusable, maintainable styles shared across documents.

## Good practices

- Use semantic HTML and reusable CSS classes.
- Keep presentation in stylesheets rather than scattering inline declarations.
- Use `:focus-visible` to provide a visible keyboard focus state.
- Keep selectors understandable and avoid unnecessary specificity.
