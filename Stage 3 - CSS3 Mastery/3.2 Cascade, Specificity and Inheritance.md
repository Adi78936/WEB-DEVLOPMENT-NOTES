# 3.2 Cascade, Specificity and Inheritance

## Interview preparation

When multiple CSS declarations target the same property on the same element, the browser resolves them through the **cascade**. A useful mental model is: origin/importance and cascade layers, specificity, scoping proximity where applicable, then source order.

The cascade does not mean “the last rule always wins.” The last rule wins only when the competing declarations otherwise have equal precedence.

## Cascade and source order

```css
p { color: navy; }
p { color: teal; } /* wins when both declarations have equal precedence */
```

Source order resolves a tie at the same precedence and specificity. A later rule does not override a more specific competing selector merely because it appears later.

## Specificity

For ordinary author selectors, specificity can be understood as four components:

```text
inline style | ID selectors | class/attribute/pseudo-class selectors | type/pseudo-element selectors
```

Examples:

```css
p { color: #333; }              /* 0-0-0-1 */
.card p { color: navy; }        /* 0-0-1-1 */
#content p { color: teal; }     /* 0-1-0-1 */
```

The ID selector wins between these examples, assuming the same origin, importance, layer, and other cascade conditions.

Notes:

- Specificity is compared by columns, not by treating the numbers as a normal decimal.
- `:where(...)` contributes zero specificity.
- `:is(...)`, `:not(...)`, and `:has(...)` take specificity from their most specific argument.
- Universal selector `*` contributes no specificity.
- Inline styles are not best represented as “a very large ID count”; the cascade has separate rules for them.

## Inheritance

Some properties pass from a parent to descendants when no other declaration overrides them. Text-related properties such as `color` and `font-family` commonly inherit. Box-model properties such as `margin` and `border` generally do not.

```css
body { color: #25302a; font-family: system-ui, sans-serif; }
```

Descendant text normally inherits the body's text color and font family. A child can specify its own value.

CSS-wide keywords:

- `inherit`: use the computed value from the parent.
- `initial`: use the property's initial value.
- `unset`: behave as `inherit` for inherited properties and `initial` otherwise.
- `revert`: roll back to the value from an earlier cascade origin.

## `!important`

```css
.notice { color: #333 !important; }
```

`!important` changes declaration priority in the cascade; it is not a specificity multiplier. Important declarations compete with other important declarations, where origin, layer, and specificity still matter. Transitions and animations also have defined cascade behavior.

Use it sparingly. Frequent use makes components harder to override and can create specificity and maintenance problems. It can be justified in limited cases such as carefully designed utility overrides or user styles.

## CSS conflicts and debugging

When a style does not appear:

1. Inspect the element and computed styles in browser developer tools.
2. Identify declarations that target the same property.
3. Compare importance, origin/layer, specificity, and source order.
4. Check whether a more specific rule, shorthand, inherited value, or media query changes the property.
5. Confirm the stylesheet loaded and the selector matches.

## Browser default styles

Browsers provide user-agent styles, such as default margins on headings and paragraphs and default button appearance. These defaults vary somewhat between browsers.

An author stylesheet can intentionally override them. Use a considered reset or normalization rather than assuming every element starts with identical styles.

## CSS reset

A reset reduces or standardizes browser defaults. A small project baseline might be:

```css
*, *::before, *::after { box-sizing: border-box; }
body { margin: 0; }
img, video { max-width: 100%; height: auto; }
```

A **reset** often removes many defaults; a **normalization** approach aims to make defaults more consistent while retaining useful behavior. Avoid resets that remove accessibility affordances such as focus outlines without replacements.

## CSS custom properties

Custom properties store reusable values and participate in inheritance:

```css
:root {
  --color-brand: #285d4b;
  --space-md: 1rem;
}

.card {
  padding: var(--space-md);
  border-color: var(--color-brand);
}
```

- Names begin with `--`.
- Read them using `var(--name)`.
- They inherit through the DOM and can be scoped to components or themes.
- A fallback can be supplied: `var(--accent, teal)`.
- Custom properties are evaluated where used; invalid values can make the consuming declaration invalid.

## Interview review

1. Does the last CSS rule always win? No; only after higher-priority cascade criteria are tied.
2. What usually beats a class selector: an ID selector or an element selector? An ID selector.
3. Does specificity alone determine the winner? No; origin, importance, layers, and other cascade rules are considered first.
4. What is inheritance? Certain property values flow from parent to descendants unless overridden.
5. What does `!important` do? Raises a declaration's cascade priority; it does not simply increase specificity.
6. Why use custom properties? Centralized, reusable, inheriting values that can support themes and component-level configuration.

## Good practices

- Prefer low-specificity, component-oriented selectors.
- Use cascade layers intentionally for large stylesheets.
- Avoid routine `!important`.
- Inspect computed styles rather than guessing at conflicts.
- Preserve visible focus indicators when resetting browser styles.
