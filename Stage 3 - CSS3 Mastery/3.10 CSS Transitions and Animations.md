# 3.10 CSS Transitions and Animations

## Interview preparation

CSS transitions animate a property as it changes between states. CSS animations can define a sequence of states with keyframes.

## Transitions

```css
.button {
  background: #285d4b;
  transition: background-color 180ms ease, transform 180ms ease;
}
.button:hover {
  background: #1d4739;
  transform: translateY(-2px);
}
```

- `transition-property`: which properties animate.
- `transition-duration`: how long the transition takes.
- `transition-timing-function`: how progress changes over time.
- `transition-delay`: how long before it begins.
- `transition` is a shorthand for these components.

Prefer animating `transform` and `opacity` for performance where appropriate. Animating layout-heavy properties such as width or top can trigger repeated layout work.

## Timing functions

Common values include `linear`, `ease`, `ease-in`, `ease-out`, `ease-in-out`, and `cubic-bezier(...)`.

Use duration and easing to communicate subtle state changes. Motion should not make users wait for essential actions.

## Transforms

Transforms change an element's visual coordinate system without changing normal-flow layout:

```css
.icon {
  transform: translateY(-2px) rotate(5deg) scale(1.05);
}
```

- `translate()` moves.
- `rotate()` rotates.
- `scale()` changes visual size.
- `skew()` slants.
- Transform functions compose in order; their order matters.
- A transform can create a stacking context and can affect containing-block behavior for descendants.

## Keyframe animations

```css
@keyframes progress {
  from { transform: scaleX(0); }
  to { transform: scaleX(1); }
}

.progress-indicator {
  transform-origin: left;
  animation: progress 800ms ease-out both;
}
```

Keyframes define intermediate states. The `animation` shorthand can set name, duration, timing, delay, iteration count, direction, fill mode, and play state.

Important properties:

- `animation-duration`: length of one cycle.
- `animation-delay`: wait before starting.
- `animation-iteration-count`: number or `infinite`.
- `animation-direction`: `normal`, `reverse`, `alternate`, or `alternate-reverse`.
- `animation-fill-mode`: whether styles apply before/after active cycles.

## Hover and loading effects

Hover effects should also have keyboard equivalents when they communicate an interactive state:

```css
.button:hover,
.button:focus-visible { filter: brightness(1.08); }
```

Loading animation should communicate real waiting state, not suggest progress that is not measured. Provide text or status semantics as well as motion.

## Reduced motion

Respect users who request reduced motion:

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    scroll-behavior: auto !important;
    animation-duration: .01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: .01ms !important;
  }
}
```

The exact response depends on the interface; remove or simplify nonessential motion while retaining clear state changes. Avoid flashing or large motion that can cause discomfort.

## Interview review

1. How does a transition differ from an animation? A transition interpolates between changed values; an animation can define a sequence with keyframes.
2. Which properties are often efficient to animate? `transform` and `opacity`, depending on the effect and browser.
3. What is a keyframe? A specified style state at a point in an animation sequence.
4. What does `animation-fill-mode` do? Controls whether animation styles apply outside the active interval.
5. Why support `prefers-reduced-motion`? It respects users who prefer less nonessential movement.

## Good practices

- Animate meaningful state changes, not everything.
- Keep interactions responsive; avoid long delays.
- Provide focus and hover states.
- Avoid layout-thrashing animations when transforms can achieve the same effect.
- Respect reduced-motion settings and avoid misleading loading progress.
