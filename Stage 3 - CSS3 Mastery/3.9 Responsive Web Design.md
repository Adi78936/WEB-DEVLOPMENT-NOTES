# 3.9 Responsive Web Design

## Interview preparation

Responsive web design adapts a layout and its content to different viewport sizes, input methods, and display conditions. It is not simply shrinking desktop content to fit a phone.

## Mobile-first and desktop-first

### Mobile-first

Write the base styles for smaller layouts, then add enhancements at wider breakpoints:

```css
.layout { display: grid; grid-template-columns: 1fr; }
@media (min-width: 48rem) {
  .layout { grid-template-columns: 16rem 1fr; }
}
```

This encourages a strong small-screen baseline and progressive enhancement.

### Desktop-first

Start with the wider layout and override it for smaller viewports:

```css
.layout { display: grid; grid-template-columns: 16rem 1fr; }
@media (max-width: 48rem) {
  .layout { grid-template-columns: 1fr; }
}
```

Either approach can work. Choose a consistent approach based on project requirements and existing code; do not blindly add conflicting breakpoints.

## Relative and viewport units

- `px`: CSS pixel; useful for fine details, but not necessarily a physical screen pixel.
- `%`: relative to a containing block or property-specific reference.
- `em`: relative to the element's computed font size for many properties; can compound through nesting.
- `rem`: relative to the root element's font size.
- `vw` / `vh`: 1% of the viewport's width / height.
- `svh`: 1% of the small viewport height, often stable with mobile browser controls shown.
- `dvh`: 1% of the dynamic viewport height, updating as browser UI expands or retracts.

Viewport height varies on mobile as browser controls change. Prefer an appropriate modern unit and a fallback when a full-height layout is needed:

```css
.hero { min-height: 100vh; min-height: 100dvh; }
```

Use units according to the relationship that should scale. Avoid making essential text depend on viewport units alone.

## Media queries and breakpoints

```css
@media (min-width: 48rem) {
  .navigation { display: flex; }
}
```

Media queries can test viewport size, orientation, color scheme, and user preferences. Choose breakpoints where the content/layout needs a change, rather than targeting a particular device model.

The viewport meta tag in HTML is needed for expected mobile layout behavior:

```html
<meta name="viewport" content="width=device-width, initial-scale=1">
```

## Flexible containers and responsive grids

```css
.container {
  width: min(100% - 2rem, 72rem);
  margin-inline: auto;
}

.card-grid {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(100%, 16rem), 1fr));
  gap: 1rem;
}
```

Use flexible widths, maximum content widths, min/max sizing, and Grid/Flexbox rather than fixed page widths.

## Responsive images

```css
img { display: block; max-width: 100%; height: auto; }
```

Use `srcset` and `sizes` to offer resolution choices, or `<picture>` for art direction and formats. Reserve image dimensions or an aspect ratio to reduce layout shift. Use `object-fit` for deliberate cropping.

## Responsive typography

```css
h1 { font-size: clamp(2.2rem, 5vw, 4.5rem); }
```

Fluid type should have sensible minimum and maximum values. Check line length and wrapping at narrow widths, large text settings, and zoom.

## Responsive navigation

A narrow viewport may require a different navigation presentation, but the menu must remain usable:

- Provide a real button to open/close a collapsed menu.
- Keep `aria-expanded` synchronized with the menu state.
- Support keyboard operation and visible focus.
- Avoid hover-only navigation.
- Ensure the opened menu fits and does not obscure essential content unexpectedly.
- Preserve an understandable focus and reading order.

## Device testing

Test more than one device width:

- Narrow mobile (around 320–360 CSS px).
- Common mobile widths (around 390–430 CSS px).
- Tablet and laptop widths.
- Desktop and large monitors.

Also test:

- Browser zoom and larger text.
- Portrait and landscape.
- Keyboard navigation.
- Reduced motion and high-contrast preferences where relevant.
- Long content, empty states, loading states, and error messages.

Use browser developer tools for initial testing, but verify important behavior on real devices and browsers as feasible.

## Interview review

1. What is responsive web design? Layout/content adaptation to viewport and user/device conditions.
2. Why mobile-first? It establishes a small-screen baseline and adds complexity as space becomes available.
3. What is the difference between `em` and `rem`? `em` is relative to contextual font sizing; `rem` is relative to the root font size.
4. Why use `min()`, `max()`, or `clamp()`? To express flexible values bounded by constraints.
5. How choose breakpoints? Based on where content or layout stops working well, not device names.
6. What are `svh` and `dvh`? Viewport-height units accounting for small and dynamically changing viewport sizes.

## Good practices

- Let content drive breakpoints.
- Prevent horizontal overflow and clipped focus indicators.
- Keep controls touch-friendly without sacrificing desktop precision.
- Support zoom, keyboard operation, and reduced motion.
- Test realistic content, not only placeholder text.
