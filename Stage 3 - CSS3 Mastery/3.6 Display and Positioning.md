# 3.6 Display and Positioning

## Display values

### `block`

A block-level box generally starts on a new line and fills available inline space by default.

### `inline`

An inline box participates in a line of text. Width and height do not behave like ordinary block dimensions, and vertical margins/padding have special layout effects.

### `inline-block`

Flows inline with surrounding content but accepts width, height, and box-model sizing more like a block.

### `none`

```css
.panel[hidden] { display: none; }
```

Removes the element and its descendants from layout and normally from the accessibility tree. Use intentionally; hidden content is not available to users until revealed.

### `visibility`

`visibility: hidden` hides an element while preserving its layout space. It differs from `display: none`.

## Positioning

### `static`

The default positioning. The element follows normal document flow; `top`, `left`, and similar inset properties do not position it.

### `relative`

The element remains in normal flow; insets can visually offset it. It also commonly establishes the containing block for absolutely positioned descendants.

```css
.card { position: relative; }
```

### `absolute`

The element is removed from normal flow and positioned relative to its nearest positioned containing block, often an ancestor with `position: relative`.

```css
.card { position: relative; }
.badge { position: absolute; top: .5rem; right: .5rem; }
```

If there is no suitable ancestor, positioning may be relative to the initial containing block.

### `fixed`

Positioned relative to the viewport in common cases and removed from normal flow. Ancestors with properties such as transforms can affect the containing block. A fixed header can obscure page content; account for it in layout and anchor scrolling.

### `sticky`

Behaves like normal flow until its scroll threshold is reached, then sticks within its scrolling container:

```css
.toolbar { position: sticky; top: 0; z-index: 2; }
```

Sticky positioning needs an inset such as `top`. It is constrained by its containing block and can be affected by scrolling/overflow ancestors.

## `z-index` and stacking contexts

`z-index` controls stacking order within stacking-context rules. It is commonly effective on positioned elements and on flex/grid items, among other cases.

A stacking context is an independent layer in which descendant z-index values are compared. It can be created by conditions such as:

- Positioned element with a non-auto `z-index`.
- `opacity` less than `1`.
- `transform`, certain filters, or `isolation: isolate`.
- Certain containment and other properties.

A child with `z-index: 9999` cannot necessarily escape its parent's stacking context and appear above every other page element. Diagnose the ancestor contexts instead of continually increasing z-index.

## Interview review

1. Difference between `display: none` and `visibility: hidden`? The former removes layout space; the latter preserves it.
2. What is removed from normal flow? Absolute and fixed positioned elements; relative and sticky generally reserve their flow space.
3. What is an absolute element positioned against? Its nearest applicable positioned containing block.
4. Why can a high z-index still appear underneath another element? Stacking contexts constrain the comparison.
5. What does sticky positioning require? A scroll relationship and a non-auto inset such as `top`.

## Good practices

- Prefer Flexbox/Grid for page layout rather than positioning everything absolutely.
- Use absolute positioning for overlays and local decoration with a meaningful containing block.
- Account for fixed/sticky UI when navigating to anchors.
- Keep stacking contexts deliberate and use a documented z-index scale.
- Preserve content when hiding elements; ensure interactive hidden panels are truly hidden and state is synchronized.
