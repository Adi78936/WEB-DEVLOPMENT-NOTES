# 3.12 Professional UI Design Fundamentals

## Interview preparation

Professional UI design connects visual presentation to usability and product goals. A polished interface is not just decoration: it helps users understand content, make decisions, and complete tasks.

## Design principles

- **Clarity:** Make purpose and available actions understandable.
- **Consistency:** Use repeated patterns for similar tasks.
- **Hierarchy:** Make the most important information easiest to notice.
- **Feedback:** Show when an action is active, completed, loading, or unsuccessful.
- **Accessibility:** Support different abilities, input methods, and preferences.
- **Restraint:** Remove decoration that competes with the user's task.

## Visual hierarchy

Visual hierarchy guides attention using size, weight, color, position, spacing, and contrast. Establish a clear order: page title, section headings, important content, supporting details, and actions.

Do not make every element visually prominent. A design in which everything is emphasized has no useful emphasis.

## Spacing systems and alignment

Use a spacing scale instead of arbitrary values:

```css
:root {
  --space-1: .25rem;
  --space-2: .5rem;
  --space-3: .75rem;
  --space-4: 1rem;
  --space-6: 1.5rem;
  --space-8: 2rem;
}
```

Consistent alignment, spacing, and grid rules make an interface feel deliberate. White space is not wasted space: it separates groups and improves scanning.

## Typography hierarchy

Define roles for:

- Display or hero text.
- Page titles.
- Section headings.
- Body copy.
- Labels and controls.
- Captions and helper text.

Use a limited type scale and ensure body text remains readable. Headings in HTML should reflect content hierarchy, not just typography.

## Color systems and contrast

Create tokens for primary, secondary, accent, surface, text, border, and status colors:

```css
:root {
  --color-text: #202a26;
  --color-surface: #fff;
  --color-brand: #285d4b;
  --color-danger: #a33e36;
}
```

- Test text and control contrast in actual contexts.
- Include labels, icons, or patterns in addition to color when showing status.
- Check both light and dark themes.
- Do not use very pale text for essential information.

## Consistency and design systems

A design system is a maintained set of design tokens, reusable components, and usage guidance. It helps multiple parts of a product remain consistent and makes changes easier to apply.

A small project can begin with:

- Color and spacing tokens.
- Typography roles.
- Common radii and borders.
- Buttons, inputs, and cards.
- Interaction and accessibility states.

Reuse should preserve meaning and usability; do not force unlike controls into one component merely to maximize reuse.

## Component styling

Style components around their purpose and states:

- Default.
- Hover (where applicable).
- Focus-visible.
- Active or selected.
- Disabled.
- Loading.
- Error or validation.

Prefer designs that can handle longer text, localization, and user zoom.

## Buttons and inputs

### Buttons

- Use clear action labels, such as “Save changes.”
- Differentiate primary, secondary, and destructive actions.
- Make targets comfortable to operate with mouse, touch, or keyboard.
- Provide visible focus and disabled states.
- Do not use a button for navigation; use an anchor for a destination.

### Inputs

- Provide persistent labels, not just placeholders.
- Indicate required fields and input formats.
- Associate help and error text with the relevant input.
- Preserve values when showing validation errors where appropriate.

## Cards and navigation

Cards should group related information and have a clear hierarchy. Use a full-card link only when the entire card represents one destination; avoid nested interactive controls that create ambiguous click targets.

Navigation should clearly indicate:

- Where the user is.
- What destinations are available.
- How a mobile menu is opened and closed.
- Focus order and keyboard operation.

## Empty, loading, and error states

### Empty states

Explain why the area is empty and give a useful next action when one exists. Do not use an empty screen that leaves users unsure what happened.

### Loading states

Show that work is in progress. Use a progress indicator only when it reflects meaningful progress; use an indeterminate indicator for work whose completion percentage is unknown. Keep status text accessible.

### Error states

Describe the problem in plain language and, when possible, explain a recovery action. Do not expose secrets, stack traces, or sensitive implementation details.

## Responsive layouts

- Start with content and tasks, then choose the layout.
- Use fluid containers, flexible grids, and appropriate breakpoints.
- Check long labels, errors, empty states, and dense tables at narrow widths.
- Preserve logical reading and keyboard order.
- Test touch targets, viewport zoom, and orientation changes.

## Practical review checklist

1. Is the primary purpose understandable at a glance?
2. Is the most important content visually prioritized?
3. Are spacing and alignment consistent?
4. Is text readable at typical and zoomed sizes?
5. Do colors have sufficient contrast and non-color status cues?
6. Can every control be operated and located with a keyboard?
7. Are loading, empty, disabled, and error states designed?
8. Does the layout work with real-length content on mobile and desktop?
9. Do controls behave as their semantic HTML suggests?
10. Is every visual element helping the task?

## Interview review

1. What is visual hierarchy? Organizing visual prominence so users can identify content importance and order.
2. Why create a spacing scale? It creates consistent rhythm and improves maintainability.
3. What is a design system? Shared tokens, components, and usage rules for consistent product design.
4. Why design empty and error states? Users need context, feedback, and a way to recover.
5. How do you improve form usability? Persistent labels, clear instructions, validation feedback, and keyboard accessibility.
6. Why should status not rely only on color? Users may not perceive or distinguish the colors; add text or another visual cue.

## Good practices

- Design for task completion, not screenshots alone.
- Make visual hierarchy, spacing, and states consistent.
- Treat accessibility and responsive behavior as core design requirements.
- Use real content when checking wrapping and layout.
- Refine based on usability tests and observed behavior, not personal preference alone.
