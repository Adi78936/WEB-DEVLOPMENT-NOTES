# 5.11 Events

## What are events?

Events communicate that something happened, such as a click, key press, input change, form submission, or page load. JavaScript can register handlers to respond.

## Event listeners

```js
const button = document.querySelector("#prepare");
button.addEventListener("click", handlePrepare);

function handlePrepare(event) {
  console.log(event.type);
}
```

Use `addEventListener()` rather than inline HTML event attributes. Named handlers can be removed later with `removeEventListener()` when the same function reference and matching options are used.

## Common event types

- `click`, `dblclick`.
- Pointer/mouse events such as `pointerdown`, `pointerup`, `mouseover`.
- Keyboard events such as `keydown` and `keyup`.
- Form/input events such as `input`, `change`, and `submit`.

Prefer pointer events when one interaction should support mouse, pen, and touch. `input` fires as a value is edited; `change` typically fires when a committed value changes. Exact timing depends on control and browser.

## Event object

The handler receives an event object:

```js
button.addEventListener("click", event => {
  console.log(event.target);
  console.log(event.currentTarget);
});
```

- `target` is the originating event target.
- `currentTarget` is the element whose listener is currently executing.
- `type` identifies the event.
- Keyboard events include `key`.
- A form submit event is fired on the form.

## Form submit events

```js
form.addEventListener("submit", event => {
  event.preventDefault();
  // Validate or submit asynchronously.
});
```

Handle form submission rather than only a submit-button click: submission may also happen by pressing Enter or through other browser actions.

## Bubbling and capturing

Most DOM events travel through phases:

1. **Capturing:** from outer ancestors toward the target.
2. **Target:** at the originating element.
3. **Bubbling:** from target back through ancestors.

By default, `addEventListener` listens during bubbling. Pass `{ capture: true }` to listen during capture. Not every event bubbles.

## Event delegation

Delegation attaches one listener to an ancestor and handles events from matching descendants:

```js
list.addEventListener("click", event => {
  const button = event.target.closest("[data-action='remove']");
  if (!button || !list.contains(button)) return;
  removeItem(button.dataset.itemId);
});
```

Benefits include handling dynamically added children and reducing many listeners. Use `closest()` and verify the match belongs to the intended container.

## `preventDefault()` and `stopPropagation()`

- `preventDefault()` cancels the browser's default action when the event is cancelable, for example native navigation or form submission.
- `stopPropagation()` prevents the event from continuing through later phases to other nodes.
- `stopImmediatePropagation()` also prevents other listeners on the same target from running.

Use these methods only when necessary. Stopping propagation can break ancestor listeners and is not the same as preventing the default behavior.

## Removing listeners and cleanup

```js
function onResize() { /* ... */ }
window.addEventListener("resize", onResize);
window.removeEventListener("resize", onResize);
```

The listener reference and relevant options must match. Event listeners attached to long-lived objects can keep closures and referenced data alive; remove them when a component or view is no longer needed.

## Interview review

1. Difference between `target` and `currentTarget`? Originating target vs. element handling the listener.
2. What is event delegation? Listening on an ancestor and handling events from descendants.
3. Difference between `preventDefault` and `stopPropagation`? Cancels browser default vs. stops event travel.
4. Why handle `submit` on the form? It covers keyboard and other submission paths, not just button clicks.
5. Do all events bubble? No.

## Good practices

- Prefer `addEventListener`.
- Support keyboard interaction and semantic controls.
- Use delegation for suitable dynamic collections.
- Avoid unnecessary propagation blocking.
- Clean up listeners on long-lived targets.
