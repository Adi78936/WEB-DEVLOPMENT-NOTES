# 5.4 Conditional Statements

## `if`, `else if`, and `else`

Conditional statements choose which code executes based on a condition:

```js
if (status === "ready") {
  startPreview();
} else if (status === "loading") {
  showSpinner();
} else {
  showUnavailable();
}
```

The first truthy condition's block runs; later branches are skipped. Braces are recommended even for one-line blocks to reduce mistakes during edits.

## Truthy/falsy conditions

An `if` condition is evaluated for truthiness. Values such as `0`, `""`, `null`, `undefined`, `false`, and `NaN` are falsy; objects and arrays, including empty ones, are truthy.

Use explicit comparisons when the valid domain is broader than truthiness:

```js
if (count !== null && count !== undefined) {
  // Count may validly be zero.
}
```

## Nested conditions

Conditions can be nested:

```js
if (user) {
  if (user.isAuthorized) {
    showDashboard();
  }
}
```

Deep nesting can be simplified using early returns, guard clauses, or well-named helper functions:

```js
if (!user || !user.isAuthorized) return;
showDashboard();
```

Do not simplify at the cost of changing behavior or obscuring important validation.

## `switch`

Use `switch` when comparing one expression against several discrete cases:

```js
switch (grade) {
  case 0:
    label = "No DR";
    break;
  case 1:
    label = "Mild DR";
    break;
  case 2:
    label = "Moderate DR";
    break;
  default:
    label = "Unknown";
}
```

- `switch` cases use strict matching (`===`-style comparison).
- `break` prevents execution from falling through to the next case.
- Fall-through can be intentional, but should be clearly documented or grouped.
- `default` handles values not matched by a case.

## Conditional expression

For choosing between two values:

```js
const label = isReady ? "Ready" : "Waiting";
```

Use `if` for multi-step statements; avoid nested ternaries that are difficult to read.

## Interview review

1. How does `else if` work? Conditions are checked in order until one is true; its branch runs.
2. What is a guard clause? An early check that exits a function for an invalid or exceptional case.
3. Does `switch` compare using loose equality? No, case matching is strict.
4. Why use braces for single statements? They improve readability and reduce bugs when code changes.
5. Is an empty array a true condition? Yes, arrays are objects and truthy.

## Good practices

- Make branches mutually understandable and handle unexpected cases.
- Prefer explicit checks when `0` or an empty string is valid.
- Use guard clauses to reduce unnecessary nesting.
- Include `break` in `switch` cases unless fall-through is intentional.
- Keep conditional expressions short and readable.
