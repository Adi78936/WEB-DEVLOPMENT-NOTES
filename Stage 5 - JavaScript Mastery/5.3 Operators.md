# 5.3 Operators

## Arithmetic operators

```js
10 + 3;  // 13
10 - 3;  // 7
10 * 3;  // 30
10 / 3;  // 3.333...
10 % 3;  // 1 (remainder)
2 ** 3;  // 8
```

`+` also concatenates strings and can coerce values. Convert explicitly when arithmetic is intended.

## Assignment operators

```js
let count = 2;
count += 1; // count = count + 1
count *= 3;
```

Compound assignments include `+=`, `-=`, `*=`, `/=`, `%=`, `**=`, and logical/nullish assignment forms such as `||=`, `&&=`, and `??=`.

## Comparison operators

- `===`, `!==`: strict equality/inequality without type coercion.
- `>`, `<`, `>=`, `<=`: relational comparisons.
- `==`, `!=`: coercive equality; usually avoid unless the coercion is deliberate and understood.

```js
0 == false;  // true (coercion)
0 === false; // false
```

Objects compare by identity, not by their contents: `{}` !== `{}`.

## Logical operators and short-circuiting

- `&&`: returns the first falsy operand, or the last operand if all are truthy.
- `||`: returns the first truthy operand, or the last operand if none are truthy.
- `!`: converts truthiness to a boolean and negates it.
- `??`: uses the right-hand value only if the left is `null` or `undefined`.

```js
const label = input || "Untitled"; // Also replaces "", 0, false.
const count = input ?? 0;           // Replaces only null/undefined.
```

Logical operators return operands, not necessarily booleans. `&&` and `||` short-circuit, so the right side may not execute.

## Increment and decrement

```js
let i = 3;
const old = i++; // old is 3; i becomes 4
const current = ++i; // i becomes 5; current is 5
```

Use the prefix/postfix distinction deliberately. In larger expressions, a separate increment statement is often easier to read.

## Ternary operator

```js
const message = isReady ? "Ready" : "Loading";
```

The conditional operator evaluates the condition, then only one of the two expressions. Use it for concise value selection, not deeply nested control flow.

## Nullish coalescing

```js
const page = options.page ?? 1;
```

`??` falls back only for `null` or `undefined`, preserving meaningful values such as `0`, `false`, and `""`. It cannot be mixed directly with `&&` or `||` without parentheses.

## Optional chaining

```js
const city = user?.address?.city;
const result = callback?.();
```

`?.` stops and returns `undefined` when the value before it is `null` or `undefined`. It prevents some access errors, but should not hide invalid states that the application ought to handle.

## Bitwise operators

Operators such as `&`, `|`, `^`, `~`, `<<`, `>>`, and `>>>` operate on 32-bit integer representations for `Number` values; BigInt has corresponding supported operations with different constraints.

Use them for genuine bit-level tasks, flags, or low-level algorithms—not as a premature optimization. JavaScript's `&&` and `||` are logical operators and are not the same as bitwise `&` and `|`.

## Operator precedence

Precedence determines how expressions group:

```js
2 + 3 * 4;   // 14
(2 + 3) * 4; // 20
```

Parentheses make intent explicit. Avoid relying on readers to memorize long precedence rules. Assignment and most binary operators associate left-to-right, while exponentiation associates right-to-left.

## Interview review

1. Why prefer `===` to `==`? It avoids implicit type coercion in equality comparison.
2. Difference between `||` and `??`? `||` uses truthiness; `??` falls back only for nullish values.
3. What does optional chaining return when a segment is nullish? `undefined`.
4. Do logical operators always return booleans? No; they return one of their operands.
5. What does postfix `i++` evaluate to? The old value, then it increments.
6. How make precedence clear? Use parentheses and simple expressions.

## Good practices

- Prefer strict equality and explicit conversions.
- Choose `??` when valid falsy values must be preserved.
- Use optional chaining for genuinely optional data.
- Use parentheses for clarity.
- Distinguish logical operators from bitwise operators.
