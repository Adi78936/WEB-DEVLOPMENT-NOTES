# 5.14 Modern JavaScript (ES6+)

## Template literals

Backtick strings allow interpolation and multiline content:

```js
const name = "Ari";
const greeting = `Hello, ${name}!`;
```

Interpolation is not HTML sanitization. Do not inject untrusted values into `innerHTML` through a template literal.

## Arrow functions

```js
const double = value => value * 2;
```

Arrow functions provide concise syntax and lexical `this`; they are not constructors and have no own `arguments`. Use regular functions when dynamic `this` or constructor behavior is required.

## Destructuring

```js
const { name, status = "new" } = project;
const [first, second, ...remaining] = items;
```

Destructuring extracts object properties or array positions. Default values apply when the value is `undefined`, not `null`.

## Spread and rest

Spread expands values:

```js
const nextItems = [...items, newItem];
const nextProject = { ...project, status: "ready" };
```

Rest collects remaining values:

```js
function logAll(first, ...remaining) {}
```

Object/array spread makes shallow copies, not deep copies.

## Modules: import and export

Named exports:

```js
// math.js
export function add(a, b) { return a + b; }
export const precision = 2;

// app.js
import { add, precision } from "./math.js";
```

Default export:

```js
// formatter.js
export default function format(value) {
  return String(value);
}

// app.js
import format from "./formatter.js";
```

- A module can have multiple named exports and at most one default export.
- Named imports use the exported name unless aliased.
- Module scope is separate from the global scope, and modules run in strict mode.
- In browsers, use `<script type="module">`; the server must serve modules with suitable MIME types and paths.
- Node.js module resolution depends on package configuration and file extensions.

## Classes

```js
class Project {
  constructor(name) {
    this.name = name;
  }

  describe() {
    return this.name;
  }
}
```

Classes provide syntax for prototype-based constructors and methods. They support inheritance, static members, private fields, and getters/setters. A class body runs in strict mode.

## Optional chaining and nullish coalescing

```js
const title = data?.project?.title ?? "Untitled";
```

Optional chaining short-circuits on `null`/`undefined`; nullish coalescing uses a fallback only for those values. Neither should conceal a required-data failure that should be reported.

## `Set` and `Map`

```js
const unique = new Set([1, 1, 2]);
unique.add(3);

const scores = new Map();
scores.set("Ari", 95);
scores.get("Ari");
```

- `Set` stores unique values using SameValueZero equality.
- `Map` stores key/value pairs and can use values of any type as keys.
- Both preserve insertion order and are iterable.
- Use a plain object for simple records with string/symbol keys; choose Map when key types or map operations are useful.

## `WeakMap` and `WeakSet`

Weak collections hold object keys/values weakly, allowing those objects to be garbage-collected when no other strong references remain:

- `WeakMap` keys must be objects or non-registered symbols where supported.
- `WeakSet` values must be eligible object keys.
- They are not enumerable and do not expose a `size`.
- Useful for associating metadata with objects without preventing their collection.

## Iterators and generators

An iterable provides an iterator through `Symbol.iterator`. `for...of` consumes iterable values.

```js
function* ids() {
  yield 1;
  yield 2;
}
```

A generator function (`function*`) returns an iterator and pauses at `yield`; generators can provide lazy sequences and custom iteration.

## Symbols

`Symbol()` creates a unique primitive value, often used as a property key:

```js
const id = Symbol("id");
const record = { [id]: 42 };
```

Symbols are not automatically included in `Object.keys()` or JSON serialization. Well-known symbols such as `Symbol.iterator` let objects customize language protocols.

## Dynamic imports

```js
const module = await import("./chart.js");
module.renderChart();
```

`import()` returns a Promise for a module namespace object and can load code on demand. It is useful for code splitting, but the imported module still must be available and errors should be handled.

## Interview review

1. Named vs. default exports? Named exports use explicit exported names; default export is one designated value per module.
2. Is spread a deep copy? No.
3. Map vs. object? Map supports arbitrary key types and dedicated map operations; objects are useful for records with property keys.
4. Why use WeakMap? Associate data with object keys without keeping those keys alive solely through the map.
5. What does a generator do? Produces an iterator that can pause at `yield`.
6. What does dynamic import return? A Promise that resolves to the module namespace.

## Good practices

- Use modules to establish clear dependencies and boundaries.
- Prefer `const` and immutable transformations where useful.
- Select Map/Set based on access and uniqueness needs.
- Keep template-literal values out of unsafe HTML sinks.
- Handle dynamic import and asynchronous module-load errors.
