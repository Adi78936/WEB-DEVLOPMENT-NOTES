# 5.6 Functions

## Function declaration

```js
function add(a, b) {
  return a + b;
}
```

Function declarations are hoisted in their scope and can generally be called before their declaration appears in the source.

## Function expression

```js
const add = function (a, b) {
  return a + b;
};
```

The function expression is assigned to a binding. The binding's initialization rules apply, so a `const` function expression cannot be called before its declaration executes.

## Parameters, arguments, and return

- **Parameters** are names in the function definition.
- **Arguments** are values supplied in a call.
- `return` gives a value back and ends the current function.
- A function without a return value returns `undefined`.

```js
function greet(name) { // name is a parameter
  return `Hello, ${name}`;
}
greet("Ari"); // "Ari" is an argument
```

## Default parameters

```js
function createLabel(name = "Untitled") {
  return name;
}
```

A default is used when the argument is omitted or `undefined`, not when it is `null`, `false`, `0`, or `""`.

## Arrow functions

```js
const square = value => value * value;
const sum = (a, b) => {
  return a + b;
};
```

- Concise syntax; a single expression can be returned implicitly.
- Arrow functions do not have their own `this`, `arguments`, or `super`; they capture lexical `this`.
- They cannot be used as constructors with `new`.
- Use a regular function when its own dynamic `this` or constructor behavior is required.

## Anonymous functions

Functions can be written without a name, often as expressions or callbacks:

```js
setTimeout(function () {
  console.log("Finished");
}, 100);
```

Named functions can make stack traces and recursion easier to understand.

## Callbacks and higher-order functions

A **callback** is a function passed to another function to be called later or as part of an operation:

```js
items.map(item => item.name);
```

A **higher-order function** accepts a function, returns a function, or both. Examples include `map`, `filter`, event-listener registration, and function factories.

## Pure functions

A pure function:

- Returns the same output for the same inputs.
- Has no observable side effects.

```js
const area = (width, height) => width * height;
```

Purity makes functions easier to test and reason about. Real applications also need side effects such as network access and DOM updates; isolate them where practical.

## Function scope and lexical scope

Variables declared inside a function are local to its scope. A function can access bindings from the scopes in which it was defined; this is lexical scoping. See the scope and execution notes for closures and the scope chain.

## Recursion

A recursive function calls itself and must have a base case:

```js
function factorial(n) {
  if (n <= 1) return 1;
  return n * factorial(n - 1);
}
```

Without a reachable base case, recursion continues until an error such as stack overflow. Deep recursion may be unsuitable when input size is large.

## Rest parameters

Rest parameters gather remaining arguments into an array:

```js
function total(first, ...remaining) {
  return first + remaining.reduce((sum, value) => sum + value, 0);
}
```

Only one rest parameter is allowed, and it must be last.

## Spread syntax

Spread expands an iterable or object into individual values/properties:

```js
const numbers = [2, 4];
const all = [1, ...numbers, 6];
const copy = { ...settings, theme: "dark" };
```

Spread creates shallow copies for arrays/objects; nested references remain shared.

## Interview review

1. Function declaration vs. expression? Declaration has declaration hoisting behavior; expression is evaluated when its assignment runs.
2. What is a callback? A function passed to another function for later invocation.
3. How does an arrow function's `this` differ? It uses lexical `this`; it does not define its own.
4. What makes a function pure? Same output for same inputs and no observable side effects.
5. Rest vs. spread? Rest gathers values; spread expands values.
6. Why does recursion need a base case? To stop recursive calls.

## Good practices

- Keep functions focused and name them by their purpose.
- Return explicit values when callers depend on results.
- Avoid deeply nested callbacks where promises or async functions improve clarity.
- Understand side effects and `this` behavior before choosing arrow syntax.
- Validate inputs at boundaries.
