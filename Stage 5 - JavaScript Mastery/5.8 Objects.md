# 5.8 Objects

## Object creation and properties

Object literals are a common way to create objects:

```js
const project = {
  name: "Image workspace",
  status: "ready"
};
```

Properties associate keys with values. Keys are strings or symbols; other property keys are converted to strings.

## Accessing and updating properties

```js
project.name;       // dot notation
project["status"];  // bracket notation
project.status = "complete";
project.owner = "Ari";
delete project.owner;
```

Use bracket notation for dynamic keys, keys with spaces, or keys that are not valid identifier syntax.

## Methods and nested objects

A method is a function stored as an object property:

```js
const project = {
  name: "Lab",
  describe() {
    return `Project: ${this.name}`;
  },
  settings: { theme: "light" }
};
```

The meaning of `this` in a method depends on how the function is called; see the scope and execution notes. Detaching a method can change its `this`.

## Destructuring and computed properties

```js
const { name, status: projectStatus = "unknown" } = project;
const key = "status";
const record = { [key]: "ready" };
```

Destructuring can rename properties and provide defaults. Defaults apply when the value is `undefined`, not when it is `null`.

## Object utility methods

```js
Object.keys(project);   // own enumerable string keys
Object.values(project); // corresponding values
Object.entries(project); // [key, value] pairs
```

`Object.assign(target, ...sources)` copies enumerable own properties from source objects to a target and mutates that target:

```js
const copy = Object.assign({}, project);
```

Object spread also creates a shallow copy:

```js
const updated = { ...project, status: "complete" };
```

Both `Object.assign` and spread are shallow: nested objects are not cloned.

## Optional chaining

```js
const theme = account?.preferences?.theme;
```

If a value before `?.` is `null` or `undefined`, the expression returns `undefined` instead of throwing. It is not a replacement for required-data validation.

## Object references and equality

Objects are reference values:

```js
const a = { count: 1 };
const b = a;
b.count = 2;
console.log(a.count); // 2
```

`a === b` is true because both bindings refer to the same object. Two separately created objects with the same properties are not strictly equal.

## Shallow copy and deep copy

A shallow copy duplicates only the top-level structure:

```js
const original = { nested: { value: 1 } };
const shallow = { ...original };
shallow.nested.value = 2; // also changes original.nested.value
```

### Structured cloning

`structuredClone(value)` creates a deep copy for supported structured-cloneable values:

```js
const duplicate = structuredClone(original);
```

- It supports many built-in data types, including cycles, but not every JavaScript value; functions and DOM nodes are not cloneable.
- It can throw for unsupported input.
- It is not a universal substitute for serialization, class-specific copy logic, or transferring ownership.
- JSON stringify/parse is limited: it loses or alters values such as `undefined`, functions, symbols, and special object types, and fails on cycles and BigInt.

For nested state, update only the required branches and preserve the rest intentionally rather than deep-cloning everything indiscriminately.

## Interview review

1. Difference between dot and bracket notation? Bracket notation supports computed/dynamic property keys.
2. Does object spread deep-copy? No, it copies top-level enumerable own properties.
3. What do `Object.keys`, `values`, and `entries` return? Own enumerable string keys, values, or key/value pairs.
4. How are objects compared with `===`? By identity/reference, not structural content.
5. When can `structuredClone` be used? For supported structured-cloneable values when a deep clone is needed.
6. What is the danger of `Object.assign({}, source)`? It is shallow and source nested objects remain shared.

## Good practices

- Prefer object literals for straightforward records.
- Use computed property access when keys are dynamic.
- Avoid deleting/reassigning structure when a clear immutable update is appropriate.
- Be explicit about reference sharing and clone depth.
- Never treat JSON round-tripping as a universal deep-copy solution.
