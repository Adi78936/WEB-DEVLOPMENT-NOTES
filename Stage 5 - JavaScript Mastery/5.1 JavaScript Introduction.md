# 5.1 JavaScript Introduction

## What is JavaScript?

JavaScript (JS) is a high-level, dynamically typed programming language used to build interactive applications. It is standardized as **ECMAScript** by Ecma International. JavaScript is not Java; they are separate languages with different designs and ecosystems.

JavaScript can run in browsers and in server-side environments such as Node.js. The language is the same, but host APIs differ: browsers provide `document` and `window`; Node.js provides APIs such as filesystem access.

## JavaScript in browsers

Browser JavaScript can:

- Respond to user events.
- Read and update the DOM.
- Validate form input for user feedback.
- Make network requests.
- Use browser APIs such as storage and canvas, subject to security restrictions.

Client-side code is visible to users and cannot be trusted to enforce security, authorization, or business rules on its own. Validate and authorize sensitive operations on the server.

## JavaScript in backend development

Runtime environments such as Node.js execute JavaScript outside the browser. Backend code can expose APIs, process requests, access databases, and run application logic. Browser-only objects such as `document` are not available in Node.js unless a separate DOM environment is provided.

## Adding JavaScript to HTML

### External script

```html
<script src="app.js" defer></script>
```

External files are easier to reuse, cache, test, and maintain.

### Internal script

```html
<script>
  console.log("Page script");
</script>
```

Useful for small demonstrations, but large scripts generally belong in separate files.

Classic scripts without `defer` or `async` can block HTML parsing. `defer` downloads in parallel, executes after parsing, and preserves order among deferred classic scripts. `async` executes as soon as ready and does not guarantee execution order.

```html
<script type="module" src="app.js"></script>
```

JavaScript modules are deferred by default and have module scope.

## Console

The browser developer console helps inspect output, warnings, and errors:

```js
console.log("Loaded");
console.warn("Unexpected value");
console.error("Could not load data");
console.table([{ name: "Sample", ready: true }]);
```

Do not log secrets or sensitive user data. Remove noisy debugging logs before production where appropriate.

## Comments

```js
// Single-line comment

/*
  Multi-line comment
*/
```

Use comments to clarify intent or non-obvious decisions, not to restate obvious code.

## Statements and expressions

- An **expression** produces a value: `2 + 3`, `user.name`, or `isReady ? "yes" : "no"`.
- A **statement** performs an action or controls execution: a declaration, `if`, loop, or `return`.

```js
const total = 2 + 3; // Declaration statement; 2 + 3 is an expression.
```

JavaScript uses automatic semicolon insertion, but consistent semicolon style can make code less ambiguous.

## Strict mode

Strict mode enables stricter parsing and some safer language behavior:

```js
"use strict";

function calculate() {
  // Strict mode applies inside this function.
}
```

- A directive at the start of a script enables strict mode for that script.
- ES modules and class bodies are strict by default.
- Strict mode helps catch mistakes such as assigning to an undeclared variable; it does not replace linting, validation, or security controls.

## Interview review

1. What is JavaScript standardized as? ECMAScript.
2. Is JavaScript the same as Java? No.
3. What differs between browser JS and Node.js? The runtime-provided host APIs and environment.
4. What is an expression? Code that evaluates to a value.
5. Why use `defer`? It loads an external script in parallel and runs it after parsing, preserving deferred classic script order.
6. Are ES modules strict? Yes, module code runs in strict mode by default.

## Good practices

- Keep substantial application code in modules or external files.
- Choose `defer`, modules, or `async` according to dependency and execution-order needs.
- Use browser DevTools for debugging.
- Never rely on client-side code as the only security boundary.
