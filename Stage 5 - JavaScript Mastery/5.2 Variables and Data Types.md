# 5.2 Variables and Data Types

## Declaring variables

```js
const projectName = "Retina Lab";
let retryCount = 0;
retryCount += 1;
```

- Prefer `const` by default; use `let` when the binding must be reassigned.
- Avoid `var` in modern code unless working with legacy code or intentionally studying its behavior.
- `const` prevents reassignment of the binding, not mutation of an object stored in it.

```js
const settings = { theme: "light" };
settings.theme = "dark"; // Allowed: the object is mutable.
// settings = {};        // TypeError: cannot reassign the const binding.
```

## `var`, `let`, and `const`

| Declaration | Scope | Redeclare in same scope? | Reassign? | Initialization |
|---|---|---:|---:|---|
| `var` | Function or global scope | Yes | Yes | Initialized to `undefined` when its binding is created |
| `let` | Block scope | No | Yes | In temporal dead zone until declaration executes |
| `const` | Block scope | No | No | Must be initialized; in temporal dead zone until declaration executes |

`var` declarations are hoisted and can create confusing behavior, especially in loops. `let` and `const` are usually clearer.

## Naming conventions

JavaScript identifiers are case-sensitive. Common conventions:

- Variables and functions: `camelCase`.
- Classes: `PascalCase`.
- Constants: `UPPER_SNAKE_CASE` often for fixed module-level constants, but ordinary `const` bindings commonly use `camelCase`.
- Use descriptive names and avoid reserved keywords.

Names may begin with a letter, `_`, or `$`; later characters may also include digits. Prefer conventional, readable identifiers.

## Primitive data types

JavaScript has seven primitive types:

- `number`: IEEE 754 floating-point numbers; includes `NaN`, `Infinity`, and `-Infinity`.
- `string`: text, written with quotes or template literals.
- `boolean`: `true` or `false`.
- `undefined`: a missing or unassigned value.
- `null`: an intentional absence of an object value.
- `bigint`: arbitrary-precision integers, written for example as `123n`.
- `symbol`: unique identifiers, often used as specialized property keys.

Primitives are immutable values. Strings, for example, cannot be changed in place; string methods produce new strings.

## Objects

Objects are non-primitive collections of properties. Arrays, functions, dates, maps, and many other structures are objects:

```js
const user = { name: "Ari", active: true };
const values = [1, 2, 3];
```

Objects are assigned and passed by reference to the same underlying object; the binding itself contains a reference value.

## Dynamic typing and `typeof`

JavaScript is dynamically typed: a variable can hold values of different types during execution.

```js
let result = 5;
result = "complete";
```

`typeof` returns a string describing a value's type:

```js
typeof 42;          // "number"
typeof "text";      // "string"
typeof undefined;   // "undefined"
typeof null;        // "object" — historical language quirk
typeof [];          // "object"
typeof (() => {});  // "function"
```

Use `Array.isArray(value)` to test for an array. Check `value === null` explicitly for null.

## Type conversion and coercion

- **Explicit conversion:** intentionally convert with `Number(value)`, `String(value)`, or `Boolean(value)`.
- **Coercion:** JavaScript converts types implicitly in some operations, such as `"5" + 1` producing `"51"`.

```js
Number("12");  // 12
Number("no");  // NaN
String(false); // "false"
```

Prefer explicit conversions at input and API boundaries. Validate `NaN` with `Number.isNaN()` when necessary.

## Truthy and falsy values

Falsy values include `false`, `0`, `-0`, `0n`, `""`, `null`, `undefined`, and `NaN`. All other values are truthy, including empty arrays `[]` and empty objects `{}`.

```js
if (items.length) {
  // Non-empty array
}
```

Do not use truthiness when `0` or `""` is a valid meaningful value; use an explicit condition.

## Interview review

1. Does `const` make an object immutable? No; it prevents reassignment of the binding.
2. How does `let` differ from `var`? `let` is block-scoped and has temporal dead zone behavior; `var` is function/global-scoped.
3. Why is `typeof null` `"object"`? Historical JavaScript behavior.
4. What is dynamic typing? Types belong to values, and a binding can refer to values of different types.
5. Is an empty array falsy? No, it is truthy.
6. What is the difference between coercion and conversion? Coercion is implicit; conversion is explicit.

## Good practices

- Use `const` unless reassignment is needed.
- Validate and convert untrusted input.
- Distinguish `null`, `undefined`, empty strings, and zero intentionally.
- Use `Array.isArray()` instead of `typeof` to identify arrays.
