# 5.9 Scope and Execution

## Scope types

- **Global scope:** bindings available outside functions/blocks, subject to script/module rules.
- **Function scope:** a `var` or parameter is available within its function.
- **Block scope:** `let` and `const` are limited to the nearest `{ ... }` block.
- **Lexical scope:** name lookup follows where code is written/defined, not where a function is called.

```js
const outer = "visible";
function run() {
  const inner = "local";
  if (true) {
    const blockValue = 1;
  }
  // blockValue is not accessible here.
}
```

## Scope chain

When code refers to an identifier, JavaScript searches the current scope, then enclosing lexical scopes, continuing outward until it finds a binding or reaches the global environment. This is the scope chain.

## Hoisting and temporal dead zone

Declarations are processed before their code executes, but different declarations behave differently:

- Function declarations are generally available throughout their scope.
- `var` bindings are hoisted and initialized to `undefined`.
- `let` and `const` bindings exist from the start of their block but cannot be accessed before their declaration is evaluated; this period is the **temporal dead zone** (TDZ).

```js
console.log(value); // ReferenceError: TDZ
let value = 3;
```

“Hoisting” is a mental model, not JavaScript moving source text. Prefer declarations before use.

## Execution context and call stack

An execution context tracks the state needed to evaluate code, including its lexical environment and `this` binding. The call stack tracks currently executing function calls:

1. A function call pushes an execution frame.
2. The function executes.
3. Returning or throwing removes that frame.

Deep synchronous recursion can exhaust the call stack.

## Closures

A closure is a function together with access to its surrounding lexical environment:

```js
function makeCounter() {
  let count = 0;
  return () => {
    count += 1;
    return count;
  };
}
const next = makeCounter();
next(); // 1
next(); // 2
```

Closures let functions retain access to bindings after the outer function has returned. They support callbacks, private state, and function factories. Long-lived closures can also retain objects in memory if references are kept unnecessarily.

## `this`

For regular functions, `this` is generally determined by the call site:

```js
const user = {
  name: "Ari",
  showName() { return this.name; }
};
user.showName(); // "Ari"
```

Extracting `const show = user.showName; show();` loses the receiver in strict mode, so `this` is `undefined` unless the function is explicitly bound. Arrow functions capture lexical `this` and do not have their own.

Constructor calls (`new`) and `call`, `apply`, and `bind` also affect `this`.

## `call`, `apply`, and `bind`

```js
function greet(prefix) {
  return `${prefix}, ${this.name}`;
}
const person = { name: "Ari" };
greet.call(person, "Hello");
greet.apply(person, ["Hello"]);
const greetPerson = greet.bind(person, "Hello");
```

- `call(thisArg, ...args)` invokes immediately with arguments listed.
- `apply(thisArg, argsArray)` invokes immediately with arguments in an array-like value.
- `bind(thisArg, ...args)` returns a new bound function; it does not invoke immediately.
- Binding does not override `this` for arrow functions.

## Prototypes and prototype chain

Objects can inherit properties from another object through their prototype. Property lookup checks the object itself, then its prototype, then successive prototypes until it reaches `null`.

```js
const base = { describe() { return "base"; } };
const child = Object.create(base);
child.describe(); // found on base
```

`Object.create(null)` creates an object with no prototype. `Object.hasOwn(obj, key)` checks for an own property without considering inherited ones.

## Constructor functions and classes

```js
function User(name) {
  this.name = name;
}
User.prototype.greet = function () {
  return `Hi, ${this.name}`;
};
const ari = new User("Ari");
```

Classes provide syntax over JavaScript's prototype-based behavior:

```js
class Admin extends User {
  constructor(name, role) {
    super(name);
    this.role = role;
  }
}
```

- Classes are not a separate classical object system; instances use prototypes.
- Class methods are placed on the prototype.
- `extends` establishes prototype inheritance; `super()` invokes the parent constructor.
- Prefer composition when it models the relationship better than inheritance.

## Interview review

1. What is lexical scope? Scope determined by source-code nesting.
2. What is the TDZ? The period before a `let`/`const` declaration is initialized when access throws.
3. What is a closure? A function retaining access to its lexical environment.
4. How is regular-function `this` determined? Primarily by how the function is invoked.
5. How does `bind` differ from `call`? `bind` returns a new function; `call` invokes immediately.
6. Are JavaScript classes prototype-based? Yes.

## Good practices

- Prefer block-scoped `let` and `const`.
- Keep closures from retaining large objects longer than needed.
- Avoid relying on implicit `this` in callbacks; bind or use an appropriate function form.
- Understand prototype inheritance when debugging property lookup.
