# 5.15 Browser Storage and Web APIs

## `localStorage`

`localStorage` stores string key/value data for an origin and generally persists across browser sessions:

```js
localStorage.setItem("theme", "dark");
const theme = localStorage.getItem("theme");
localStorage.removeItem("theme");
```

It is synchronous, can be restricted or unavailable, and should not hold secrets. Handle exceptions and do not store sensitive authentication data in it.

## `sessionStorage`

`sessionStorage` stores string key/value data for an origin and a top-level browsing context, commonly a tab. It generally lasts for that page session; reloading preserves it, closing the tab ends it.

Storage APIs can throw (for example, due to browser policy or quota). Treat storage as optional persistence rather than a guaranteed database.

## Storage events

The `storage` event can notify other documents when local storage changes:

```js
window.addEventListener("storage", event => {
  if (event.key === "theme") updateTheme(event.newValue);
});
```

The event is generally fired in other same-origin documents, not in the window that made the change. Session-storage event behavior is scoped to related browsing contexts. Do not use it as a guaranteed cross-device synchronization mechanism.

## Cookies

Cookies are small name/value data sent with HTTP requests according to their domain, path, expiry, and security attributes:

- `Secure`: send only over HTTPS.
- `HttpOnly`: inaccessible to page JavaScript; set by the server.
- `SameSite`: controls cross-site sending behavior and helps mitigate some CSRF scenarios.
- `Path`, `Domain`, `Expires`, and `Max-Age`: scope and lifetime controls.

Cookies may be used for server-managed sessions, but must be configured carefully. `HttpOnly` prevents JavaScript access; it does not prevent all attacks. Cookie authentication still needs appropriate CSRF and authorization protections.

## Browser history

The History API manipulates same-origin session history:

```js
history.pushState({ page: "projects" }, "", "/projects");
history.replaceState({ page: "projects" }, "", "/projects");
window.addEventListener("popstate", handleBackForward);
```

- `pushState()` adds a history entry; `replaceState()` updates the current one.
- These calls do not automatically fetch content or render a route.
- Handle `popstate` for back/forward navigation in client-side applications.

## Location API

`window.location` exposes the current URL and navigation operations:

```js
const params = new URLSearchParams(location.search);
const page = params.get("page");
location.assign("/overview");
```

Assigning a new URL can trigger navigation. Validate untrusted redirect destinations to avoid open-redirect issues.

## Geolocation API

```js
navigator.geolocation.getCurrentPosition(
  position => console.log(position.coords.latitude),
  error => console.error(error),
  { timeout: 5000 }
);
```

Geolocation generally requires a secure context and user permission. Handle denial, unavailable data, and timeouts. Request location only when it is needed and clearly explain why.

## Clipboard API

```js
await navigator.clipboard.writeText("Copied text");
```

Clipboard access is subject to browser support, secure-context requirements, permissions, and user-activation policies. Handle rejection and provide fallback or visible feedback; never claim copy succeeded before the Promise fulfills.

## File API

The File API allows a page to inspect files the user explicitly selects or drops:

```js
const file = input.files?.[0];
if (file) {
  const text = await file.text();
}
```

Use a file input or user-initiated drag-and-drop. Validate file size, type, and content; an `accept` attribute is only a chooser hint. Do not assume the filename or MIME type proves the content is safe.

## `FormData`

`FormData` represents form fields and files for submission:

```js
const formData = new FormData(form);
formData.append("source", "browser");
await fetch("/upload", { method: "POST", body: formData });
```

When using it with `fetch`, do not manually set `Content-Type: multipart/form-data`; the browser supplies the required boundary. The receiving server must validate and authorize the upload.

## `URL` and `URLSearchParams`

```js
const url = new URL("/search", location.origin);
url.searchParams.set("q", "retinal image");
console.log(url.href);
```

`URL` safely parses and composes URLs; `URLSearchParams` reads and writes query parameters with appropriate encoding. Validate schemes and destinations when handling untrusted URLs.

## Intersection Observer

Observes intersection between a target and a viewport or root container:

```js
const observer = new IntersectionObserver(entries => {
  for (const entry of entries) {
    if (entry.isIntersecting) loadPreview(entry.target);
  }
});
observer.observe(target);
```

Useful for lazy loading, visibility tracking, and scroll-triggered behavior without continuously calculating positions in a scroll handler. Call `disconnect()` or `unobserve()` when no longer needed.

## Mutation Observer

Observes DOM changes:

```js
const observer = new MutationObserver(records => {
  console.log(records);
});
observer.observe(container, { childList: true, subtree: true });
```

Use it when a component must react to DOM mutations outside its direct control. Disconnect it when finished; unnecessary observation can create performance costs or feedback loops.

## Web Workers

Web Workers run JavaScript off the main thread and communicate through messages:

```js
const worker = new Worker("processor.js");
worker.postMessage({ action: "process" });
worker.addEventListener("message", event => handleResult(event.data));
```

- A worker has no DOM access.
- Messages are structured-cloned or transferred.
- Workers are useful for CPU-intensive tasks that would otherwise block the interface.
- Use `worker.terminate()` or a worker shutdown message when appropriate.
- Worker creation, module support, and CSP configuration should be checked for the target application.

## Interview review

1. localStorage vs. sessionStorage? Persistence across sessions vs. tab-scoped page session.
2. Are Web Storage values typed? No, they are strings.
3. What makes cookies different? They can be automatically sent with matching HTTP requests and have server-oriented security attributes.
4. Does `pushState()` render a new page? No; the application must update its UI and handle `popstate`.
5. Can a worker access the DOM? No.
6. What does Intersection Observer help avoid? Frequent manual scroll-position calculations for visibility checks.
7. Should you set multipart content type with FormData? No; let the browser add the boundary.

## Good practices

- Treat storage as fallible and non-secret.
- Request sensitive permissions only with clear user context.
- Validate files and URLs rather than trusting metadata.
- Clean up observers and workers.
- Use workers for substantial CPU work, not trivial operations.
